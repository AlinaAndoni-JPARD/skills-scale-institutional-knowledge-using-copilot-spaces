# OctoAcme — New Team Member Onboarding

## Purpose
Accelerate the onboarding of new team members by providing a clear, step-by-step guide to OctoAcme processes, tools, and culture.

## Onboarding Timeline
- **Week 1:** Environment setup, role orientation, meet the team
- **Week 2:** Deep-dive into assigned project and processes
- **Week 3:** Shadow current team members and attend key meetings
- **Week 4:** Begin independent contributions with pair programming support
- **Weeks 5-8:** Ramping up, increasing autonomy, joining full meetings

## Pre-Arrival (Before Day 1)

### By Hiring Manager
- [ ] Create accounts (GitHub, Slack, project tools, VPN, etc.)
- [ ] Send welcome email with first-day logistics
- [ ] Assign onboarding buddy (preferably on same team)
- [ ] Set up workspace, hardware, and access
- [ ] Add to relevant Slack channels

### By Onboarding Buddy
- [ ] Review new hire's background and role
- [ ] Prepare initial one-on-one meeting agenda
- [ ] Flag any current fires or context to know

## Week 1: Environment & Orientation

### Day 1
- [ ] Welcome and orientation meeting with manager
- [ ] Review OctoAcme Project Management Overview
- [ ] Set up development environment and GitHub access
- [ ] Meet onboarding buddy; schedule daily check-ins
- [ ] Join key Slack channels

### Day 2–3
- [ ] Read assigned project's one-pager and roadmap
- [ ] Clone relevant repositories; verify build and tests pass
- [ ] Review team's Definition of Done and branching conventions
- [ ] Attend team standup and observe process
- [ ] Review recent retrospective notes (current challenges)

### Day 4–5
- [ ] Meet with Project Manager — understand current milestones and risks
- [ ] Meet with Product Manager — learn success metrics and roadmap
- [ ] Review open pull requests and recent commits
- [ ] Complete onboarding buddy's team orientation (tools, culture, norms)
- [ ] Schedule next week's shadowing and pair programming sessions

## Week 2: Process Deep-Dive

### Guided Reading (with buddy or manager)
- [ ] OctoAcme Roles & Personas — understand your role and peers
- [ ] OctoAcme Project Planning — how we break down work
- [ ] OctoAcme Execution & Tracking — daily standups, PRs, QA
- [ ] OctoAcme Risk Management & Communication — how we escalate issues
- [ ] OctoAcme Release & Deployment — how we ship

### Meetings to Attend & Observe
- [ ] Daily standup (observe, then start contributing)
- [ ] Weekly delivery sync or sprint planning
- [ ] Project kickoff or planning session (if one is scheduled)
- [ ] 1:1 with direct manager to discuss role and expectations

### First Hands-On Task
- [ ] Work on a small, well-defined issue marked "good first issue"
- [ ] Create a branch following team conventions
- [ ] Open a PR with proper description (link issue, describe approach)
- [ ] Request review from onboarding buddy
- [ ] Iterate on feedback and merge (with buddy's approval)

## Week 3: Shadowing & Collaboration

### Pair Programming Sessions
- [ ] Spend 2–3 hours pairing with different team members
- [ ] Shadow code reviews and ask questions
- [ ] Observe a design discussion or technical decision-making

### Meeting Participation
- [ ] Attend full standup and ask questions
- [ ] Observe pull request review process
- [ ] Sit in on a retrospective or planning session
- [ ] Join weekly stakeholder or product sync

### Deeper Contributions
- [ ] Take on 2–3 small-to-medium issues independently
- [ ] Request reviews and learn PR feedback norms
- [ ] Debug or investigate an existing issue with buddy guidance

## Week 4 Onwards: Ramping Up

### Increasing Autonomy
- [ ] Begin taking on medium-sized features independently
- [ ] Lead one pairing session for a new contributor (pay it forward)
- [ ] Propose a small process improvement or doc update
- [ ] Attend and contribute fully to all team meetings

### Check-in Points
- [ ] **End of Week 2:** Manager check-in — how's the ramp? Any blockers?
- [ ] **End of Week 4:** Informal buddy feedback — ready for independence?
- [ ] **End of Week 8:** Formal check-in with manager — are you set for success?

## Onboarding Checklist by Role

### For Developers
- [ ] GitHub access configured, SSH keys set up
- [ ] Local development environment fully functional
- [ ] Test suite runs locally without errors
- [ ] Can merge and deploy a change (with review)
- [ ] Understands PR review process and code style
- [ ] Familiar with team's tech stack and dependencies
- [ ] Knows how to escalate technical blockers

### For Product Managers
- [ ] Access to project management tools (Jira, GitHub Projects, etc.)
- [ ] Added to stakeholder communication lists
- [ ] Understanding of product roadmap and current priorities
- [ ] Knows how to file issues and define acceptance criteria
- [ ] Familiar with success metrics and how they're tracked
- [ ] Understands dependency and risk communication process

### For Project Managers
- [ ] Access to all project tracking and communication tools
- [ ] Understands current project state, timeline, and risks
- [ ] Knows escalation paths and decision-makers
- [ ] Can run a standup or planning meeting
- [ ] Familiar with resource allocation and capacity planning
- [ ] Knows release and deployment procedures

### For QA/Testers
- [ ] Test environment access configured
- [ ] Understands Definition of Done testing requirements
- [ ] Can create, assign, and triage bugs in issue tracker
- [ ] Familiar with regression testing scope
- [ ] Knows release testing and smoke test procedures
- [ ] Can use project board to coordinate with developers

## Onboarding Buddy Responsibilities

- Greet new hire on Day 1
- Pair for at least 3 hours in Week 1
- Review first PR before it goes to wider review
- Be available for quick questions via Slack
- Check in daily for first 2 weeks
- Share cultural norms and unwritten rules
- Celebrate first merged PR! 🎉

## Manager Responsibility

- Schedule 1:1s throughout onboarding
- Provide constructive feedback at end of Week 2 and 4
- Adjust expectations if ramp is slower or faster
- Celebrate completion of onboarding
- Gather feedback on onboarding process for continuous improvement

## Post-Onboarding (Week 9+)

- [ ] Schedule retrospective with manager on onboarding experience
- [ ] Document any gaps in this guide and create PR to improve it
- [ ] Once ramped, consider becoming an onboarding buddy for future hires
- [ ] Join on-call rotation (after 4 weeks minimum)

## Continuous Improvement

After each onboarding, capture feedback:
- What helped the most?
- What was confusing or outdated?
- What should be added to the guide?
- Update this document with improvements
